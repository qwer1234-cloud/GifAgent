# GIF 动作完整性保护设计

## 状态

- 日期：2026-07-29
- 状态：规格已确认，等待实施
- 前置能力：`2026-07-29-transition-aware-gif-extraction-design.md`
- 用户确认的优先级：动作叙事完整优先，循环自然次之

## 背景与问题

当前自适应 GIF 管线先对离散帧执行 VLM 评分，再按时间距离和分数合并候选。最终窗口围绕 `best_frame` 使用约 40% 前置、60% 后置的固定偏置生成。该方法能够把高分画面放进 GIF，但不理解动作是否经历了准备、开始、高潮、收势和完成，因此可能：

- 从人物已经开始转身、起身或拥抱之后才进入；
- 在动作尚未完成时结束；
- 为追求固定时长而包含过多静止内容；
- 在完整动作超过当前窗口时截取中间片段；
- 为改善循环而错误裁掉动作起势或收势。

已经实现的转场保护解决了“一个 GIF 跨越多个镜头”的问题，但它只提供镜头安全边界，不判断镜头内部的动作语义边界。动作完整性必须建立在转场安全段之上，且不得重新扩展到已确认的转场之外。

## 已确认的产品规则

1. 动作叙事完整性是第一优先级，首尾循环自然是第二优先级。
2. 正常目标时长为 4–12 秒。
3. 2–4 秒的短动作如果自身完整，可以直接保留，不强行补长。
4. `adaptive.max_duration` 默认扩展为 20 秒，并作为所有导出路径的硬上限。
5. 只有为了保留完整动作时才允许从 12 秒继续扩展到 20 秒。
6. 超过 20 秒的动作优先在自然阶段边界拆成多个 GIF，每个子 GIF 独立评分和排序。
7. 动作边界不可靠时回退当前固定 40/60 窗口，以保持候选产量。
8. 固定窗口回退也必须裁剪在转场安全段内，不能撤销已确认的转场边界。
9. 缓慢上移、平移和轻微缩放等连续运镜可以保留，不应被误认为主体动作或动作拆分点。
10. 不为了循环效果裁掉动作核心，也不自动使用倒放或乒乓循环。

## 目标

1. 在转场安全段内识别动作准备、开始、高潮、收势和完成边界。
2. 对明显主体动作自动扩展或收缩固定窗口，使动作起止更完整。
3. 对超过 20 秒的多阶段动作，在自然停顿或语义阶段变化处拆分。
4. 对微笑、拥抱和递物等低运动语义动作提供受限的 VLM 时序复核。
5. 保持 direct、旧批处理和 task-engine staged 路径的动作边界一致。
6. 保持现有产量：不可靠时回退，不因单个候选失败而使视频任务失败。
7. 记录可复盘的完整度、循环质量、置信度、边界来源和回退原因。
8. 复用转场分析证据，避免每个候选重复完整解码。

## 非目标

- 第一版不引入姿态识别、目标跟踪或深度动作识别模型。
- 不以单帧 VLM 评分直接推断动作开始和结束。
- 不允许 VLM 自由生成时间戳；VLM 只能从算法提供的候选边界中选择。
- 不重写现有 embedding、时间去重、Preference Memory 或最终排名体系。
- 不自动删除低循环质量候选。
- 不要求第一版识别人物身份或跨镜头延续同一动作。
- 不修改或删除历史 GIF、数据库记录和已有结果文件。

## 总体处理顺序

候选处理顺序固定为：

```text
VLM 帧评分
  -> 时间候选合并
  -> 构建最长 30 秒分析窗口
  -> transition_guard 生成转场安全段
  -> action_boundary 在安全段内识别动作核心
  -> 动作扩展/裁剪/拆分/固定窗口回退
  -> 子段最佳帧选择与必要的 VLM 复评
  -> embedding/temporal 去重
  -> 全局排序与 max_output
  -> 原样边界 GIF 导出
```

30 秒是低分辨率分析范围，不是 GIF 时长。默认围绕最佳帧沿用 40% 前、60% 后的上下文偏置，并在视频首尾处夹紧。分析窗口用于判断动作是否在当前导出上限之外仍在继续；任何最终输出仍受 20 秒硬上限约束。

转场保护必须先于动作边界判断。`action_boundary` 只能在 `transition_guard` 返回的安全段中工作。动作处理完成后，候选写入不可重新扩展的边界标记；direct FFmpeg 导出和 staged `gif_clip` 都必须原样使用该边界。

## 共享服务与模块边界

### `app/services/action_boundary.py`

新增纯服务模块，负责在一个转场安全段内分析动作边界，不负责 embedding、排名、GIF 编码或数据库写入。

建议接口：

```text
analyze_action_segment(
    video_path,
    safe_start_s,
    safe_end_s,
    anchor_ts_s,
    candidate,
    temporal_evidence,
    config,
) -> ActionBoundaryResult
```

`ActionBoundaryResult` 至少包含：

- 原安全段和最佳帧锚点；
- 检测到的动作候选边界；
- 最终动作段列表；
- 动作开始、高潮和结束证据；
- `action_boundary_mode`；
- `action_completeness_score`；
- `action_boundary_confidence`；
- `loop_quality_score`；
- 是否需要子段重新评分；
- 拆分、回退或低循环质量原因；
- 算法版本和 JSON 安全的诊断指标。

### 共享时间证据

转场保护与动作检测需要共享低分辨率帧、时间戳、全局仿射变换和补偿后残差。实现时应抽取一个内部 `TemporalEvidence`/`TemporalEvidenceCache` 边界，或由 `transition_guard` 提供等价的临时证据对象。

约束：

- 以视频标识、采样时间、宽度和 FPS 为缓存键；
- 相邻候选窗口重叠时复用已解码帧；
- 动作检测从转场扫描证据下采样到约 4 FPS；
- 只补取缺失时间点，不为同一候选重新完整运行一次 FFmpeg 解码；
- 大型帧图像不写入 manifest，只记录可序列化摘要；
- 缓存仅影响性能，不影响确定性结果。

### 候选物化

direct 和 staged 路径应调用同一个候选物化函数。该函数按以下顺序执行：

1. 根据最佳帧建立分析窗口。
2. 调用转场保护并获得一个或多个安全镜头段。
3. 对每个满足最小时长的安全段调用动作边界服务。
4. 将动作拆分结果 fan-out 为普通候选。
5. 为没有已有评分帧的子段抽取代表帧并复评。
6. 写入不可扩展标记后再执行 embedding、时间去重、clip ID 和排名。

## CV 动作边界检测

### 采样与运动补偿

每个安全段默认按约 4 FPS 分析，图像宽度复用转场扫描的 320 px。对相邻帧使用现有特征跟踪和 RANSAC 仿射模型估计全局平移、缩放和轻微旋转，将后一帧对齐到前一帧。

动作检测使用补偿后的主体残余变化，而不是原始像素变化。至少计算：

- 补偿后的残余运动能量；
- 变化像素区域比例；
- 局部运动聚类的面积和持续时间；
- 残余运动速度与加速度；
- 全局仿射运动方向和连续性；
- 结构、边缘和亮度稳定程度；
- 稳定区间持续时间。

纯全局连续运动、仿射拟合良好且补偿后残差低时，标记为 `ambient_camera_motion`。该模式保持转场安全的现有固定窗口，不尝试寻找主体动作边界，也不因动作完整度未知而丢弃。

### 自适应运动曲线

残余运动曲线采用中值滤波和轻量平滑处理。阈值从当前安全段的稳健分位数和中位绝对偏差计算，不以单个固定像素差覆盖所有影片。

边界规则：

- 稳定基线后出现持续残余运动，形成动作开始候选；
- 动作峰值后残余运动持续回落并稳定，形成动作结束候选；
- 短于约 0.5 秒的运动低谷被桥接，避免一次动作因瞬间停顿被误拆；
- 持续约 1 秒以上的稳定低谷可以成为多阶段动作拆分候选；
- 开始前和结束后都存在稳定证据时，完整度提高；
- 动作在分析窗口边缘仍保持活跃时，标记为可能截断并降低置信度。

算法应生成至多三组按置信度排序的开始/结束候选，而不是立即提交单一结果。

## 受限 VLM 时序复核

VLM 只用于高分但 CV 边界置信度不足的候选，默认要求：

- `action_vlm_verify_enabled=true`；
- 候选 `gif_worthiness >= action_vlm_min_worthiness`；
- 每个候选最多调用一次。

从动作分析段选取 6–8 个带编号和时间标签的代表帧组成时序输入。VLM 输出严格 JSON，并且只能：

- 判断是否存在可描述动作；
- 从 CV 给出的候选边界编号中选择一组；
- 判断首帧、锚点帧和尾帧处于 `preparation`、`ongoing`、`recovery`、`complete` 或 `unknown`；
- 给出动作标签、是否完整、置信度和简短理由。

VLM 不得返回自由时间戳。解析失败、超时、无有效候选或置信度不足时，进入固定窗口回退。

融合规则：

1. CV 置信度达到 `action_boundary_confidence_threshold` 时直接使用 CV 边界。
2. CV 低于阈值但候选分数达到 VLM 门槛时，调用一次 VLM。
3. VLM 选择有效候选且置信度达标时，采用该候选。
4. CV 与 VLM 有轻微分歧时，选择不跨转场且不超过 20 秒的较宽边界。
5. 无法可靠融合时使用转场安全段内的固定 40/60 窗口。

## 完整度与置信度

`action_completeness_score` 和 `action_boundary_confidence` 必须分开：

- 完整度描述所选窗口包含完整动作的程度；
- 置信度描述系统对边界判断的把握。

第一版完整度由以下归一化分量组成：

- 25%：动作开始前的稳定/准备证据；
- 30%：动作结束后的收势/稳定证据；
- 20%：动作高潮是否完整包含；
- 15%：动作核心是否未贴住最终窗口边缘；
- 10%：可用时的语义确认。

未调用 VLM 时语义确认分量使用中性值，不得把“没有调用 VLM”当作失败。`ambient_camera_motion` 和固定窗口回退允许完整度为 `null`，避免生成虚假的精确分数。

## 时长与拆分

### 单动作窗口

- 最小导出时长继续使用现有 `min_duration=2`。
- 4–12 秒是首选范围。
- 完整动作短于 4 秒时只增加安全上下文，不强制补足到 4 秒。
- 完整动作长于 12 秒时，只要缩短会切掉动作核心，可以继续扩展。
- 任何最终窗口不得超过 `max_duration=20`。
- 默认在检测到的动作核心前保留约 0.4 秒、结束后保留约 0.6 秒；安全段不足时优先保留动作核心。

### 长动作拆分

动作超过 20 秒时，按以下优先级选择拆分点：

1. 转场安全边界；
2. 持续稳定或姿态停顿；
3. 残余运动曲线的明显低谷；
4. VLM 确认的语义阶段切换。

每个子段必须重新选择最佳帧、独立评分、去重和排名，并记录 `action_split_index` 与 `action_split_count`。所有子段统一参与原有 `max_output` 限制。

如果连续动作超过 20 秒且没有可靠拆分点，VLM 尝试选择不超过 20 秒的最完整子事件。仍无法判断时，围绕原最佳帧使用转场安全的固定窗口，并记录 `long_action_split_fallback`。

## 循环质量

循环调整只在动作核心之外的前后缓冲区内执行。默认允许在边界附近 `action_loop_adjust_s=0.75` 秒范围内搜索更自然的首尾组合。

`loop_quality_score` 初始由以下归一化分量组成：

- 40%：全局运动补偿后的结构相似度；
- 25%：颜色与亮度分布相似度；
- 20%：主体变化区域的位置相似度；
- 15%：首尾运动方向连续性。

允许的调整：

- 向安全段外侧扩展少量上下文；
- 裁掉动作核心之外的少量静止缓冲；
- 在多个同等完整边界中选择循环分数更高的一组。

禁止的调整：

- 裁掉动作准备、起势、高潮、收势或完成证据；
- 越过已确认转场；
- 超过 20 秒；
- 自动倒放或生成乒乓循环。

循环质量较低时仍可导出并记录原因，不能覆盖动作完整性决策。

## 配置与界面

普通设置页只增加两个可见开关，并提供中文 `?` 帮助：

```yaml
adaptive:
  action_guard_enabled: true
  action_vlm_verify_enabled: true
```

现有设置调整：

```yaml
adaptive:
  min_duration: 2
  max_duration: 20
```

高级参数只保留在 YAML：

```yaml
adaptive:
  action_analysis_window_s: 30
  action_preferred_min_duration_s: 4
  action_preferred_max_duration_s: 12
  action_scan_fps: 4
  action_boundary_confidence_threshold: 0.65
  action_loop_adjust_s: 0.75
  action_vlm_min_worthiness: 0.60
  action_fallback_mode: fixed_window
```

配置提取必须验证：

- `2 <= min_duration <= action_preferred_min_duration_s`；
- `action_preferred_min_duration_s <= action_preferred_max_duration_s <= max_duration`；
- `max_duration <= action_analysis_window_s`；
- `action_scan_fps > 0`；
- 所有分数阈值在 `[0, 1]`；
- 当前第一版只接受 `action_fallback_mode=fixed_window`。

任务启动时冻结完整动作配置、算法版本和配置 hash。两个配置 preset、direct 模式、task-engine 配置快照和 UI 保存/重载必须保持一致。

## 结果字段与可观测性

每个动作候选至少记录：

- `action_boundary_mode`：`cv`、`hybrid_vlm`、`ambient_camera_motion` 或 `fallback_fixed`；
- `action_start_ts`、`action_peak_ts`、`action_end_ts`；
- `action_completeness_score`；
- `action_boundary_confidence`；
- `loop_quality_score`；
- `action_split_index`、`action_split_count`；
- `action_split_reason`；
- `action_vlm_verified`；
- `action_fallback_reason`；
- `action_analysis_version`；
- 最终不可扩展窗口标记。

运行汇总记录：

- 输入候选数；
- CV 确认数；
- 扩展、裁剪和拆分数；
- `ambient_camera_motion` 数；
- VLM 复核、成功和失败数；
- 固定窗口回退数及原因；
- 低循环质量数；
- 动作处理前后候选数；
- CV 耗时、VLM 额外调用数和总耗时。

Review 页面使用简洁摘要，不增加必需操作：

```text
动作完整 0.86 | 循环 0.62 | 混合检测 | 拆分 1/2
```

完整诊断信息保留在候选详情和结果 JSON 中。

## Direct 与 staged 接入

### Direct

在时间候选合并后、embedding/temporal 去重前执行转场和动作候选物化。动作拆分创建的子段在没有已有评分帧时抽取代表帧并复评。最终导出看到不可扩展标记时原样使用 `start_ts/end_ts`。

### Task-engine staged

生产阶段仍保持：

```text
discover -> sample -> vlm -> refine -> synthesize
  -> rank_dedup -> gif_clip -> materialize
```

动作边界处理位于 `rank_dedup` 内，并且发生在 embedding、时间去重、clip ID 和 GIF fan-out 之前。`rank_dedup` 必须接收源视频路径、冻结配置和 `synthesize` 的评分帧证据。

`gif_clip` 只导出已经确认的动作安全窗口。旧 manifest 没有不可扩展标记时继续使用共享固定窗口；新 manifest 有标记时禁止重新居中、加时或解释边界。

## 错误处理与兼容

- 动作低分辨率解码失败：重试一次；仍失败则使用转场安全的固定窗口。
- 全局运动估计失败：使用未补偿残余指标降低置信度；不足时回退。
- VLM 超时、解析失败或返回无效候选：使用 CV 结果；CV 也不可靠时回退。
- 单个候选失败：记录原因并继续，不使整部视频失败。
- 所有候选均回退：任务仍可完成，并在汇总中标记动作检测需要关注。
- 源视频、FFmpeg 或基础任务阶段失败：沿用现有任务错误分类，不删除历史数据。
- 所有输出数值必须为有限 JSON 数值；无法计算的分数写 `null`。
- `action_guard_enabled=false` 时恢复转场保护后的现有固定窗口行为。
- 旧 manifest 没有动作字段时按固定窗口兼容。
- 回滚只影响新任务，不删除已有 GIF、数据库记录或结果文件。

## 测试设计

### 单元与合成视频

新增动作边界服务测试，使用确定性 OpenCV 合成视频覆盖：

1. 静止、起身、站稳，开始和结束误差不超过 0.75 秒。
2. 转身、挥手、拥抱和递物等不同节奏。
3. 纯缓慢上移或平移，必须返回 `ambient_camera_motion` 或固定窗口，不误扩展。
4. 镜头移动同时主体动作，补偿后仍识别动作边界。
5. 微笑等低运动语义动作，通过模拟 VLM 响应选择正确候选。
6. 多阶段动作超过 20 秒，在自然低谷拆分。
7. 无可靠拆分点，记录 `long_action_split_fallback`。
8. 动作邻近硬切、渐变和闪白，最终动作窗口不跨确认边界。
9. 循环微调只修改缓冲区，不进入动作核心。
10. 动作位于视频开头或结尾时正确夹紧。
11. 失败、超时、非法配置和非有限指标安全回退。
12. 输出字段严格 JSON 可序列化。

### 管线回归

direct 和 staged 生产测试验证：

- 相同输入得到一致的动作边界与拆分结果；
- 动作处理发生在 embedding、时间去重、clip ID 和 fan-out 之前；
- 拆分后的子段重新选择最佳帧并按需复评；
- 所有最终 GIF 时长位于 2–20 秒；
- 不可扩展标记在最终 FFmpeg 边界生效；
- 旧 manifest 仍按固定窗口兼容；
- 所有子段继续受 `max_output` 约束；
- 单候选动作检测失败不使任务崩溃；
- 配置 UI、保存、重载、任务快照和 provenance 包含新字段。

## 真实样本验收

建立至少 30 个带人工动作边界的真实片段，并与当前固定窗口版本做盲测。样本应包含明显身体动作、低运动表情/互动、连续运镜、长动作和多阶段动作。

验收门槛：

- 动作起止视觉完整率不低于 85%；
- 相比固定窗口基线，动作完整性盲测偏好胜率不低于 70%；
- 已确认硬转场进入最终 GIF 的数量为 0；
- 缓慢连续运镜样本不得出现新增误拆分；
- 100% 最终 GIF 时长位于 2–20 秒；
- 输出尽量集中在 4–12 秒，并单独报告 12–20 秒占比；
- 因固定窗口回退存在，总候选产量不得比基线下降超过 5%；
- VLM 复核调用数不超过动作候选数的 25%。

验证报告必须包含：

- 精确运行命令和冻结配置 hash；
- 基线与新版本候选数；
- 动作扩展、裁剪、拆分和回退统计；
- VLM 调用比例和失败原因；
- 动作完整性与循环质量盲测结果；
- 转场回归和连续运镜保留结果；
- 目标 GIF 路径或 manifest；
- 无法完成的验收项，不得把部分验证写成完整通过。

## 版本与回滚

动作算法使用独立的 `action_analysis_version=1`，manifest schema 随新增字段升级。任务配置冻结算法版本和所有动作参数。

回滚方式：

1. 将 `action_guard_enabled=false`，恢复转场保护后的固定窗口行为；
2. 保留 `max_duration=20` 或由用户单独改回其他值；
3. 不删除已经生成的 GIF、Review 历史、数据库记录或配置快照。

任何后续阈值校准必须通过真实样本盲测和 provenance 记录完成，不能通过未冻结的环境变量悄然改变生产行为。
