## 2. 背景与问题

GifAgent 当前已经具备候选发现、单帧美学评分、动作完整性、转场保护、循环质量以及偏好重排等能力，但这些信号分散在不同阶段，最终排序仍容易过度依赖代表帧和单一视觉模型。

这会造成三类问题：

1. 单帧好看但连续片段存在抖动、失焦、错误曝光、转场或动作残缺时，候选仍可能进入高位。
2. 当前观感较差、但通过轻量曝光或原始像素内重构图即可明显改善的片段，可能被过早丢弃。
3. 成人与非成人内容可能因为模型拒答或语义偏好，被误当成美学质量差；这违背内容中立的客观质量评价目标。

本设计把客观质量判断建模为“工作流级 MoE”：多个不同信号族的专家各自产出结构化证据，由统一的视觉大模型裁决；确定性硬门槛仍由 Core 执行，不能被大模型覆盖。

## 3. 目标

1. 使用多个互补专家共同评价画面技术质量、空间美学、时间连续性、动作完整性、电影语言和循环质量。
2. 由统一视频视觉模型基于原始媒体、联系表和专家证据，给出可解释的最终决策。
3. 优先保证自动拒绝的高精度，降低把好片段或可修复片段误删的概率。
4. 对曝光、色调或构图稍作调整即可改善的候选，输出可复现的非生成式修复方案并保留。
5. 成人与非成人内容使用完全相同的美学维度、阈值和判定流程；模型拒答只能形成弃权，不能形成负分。
6. 所有结论具有版本、模型、配置、输入和提示词溯源，并能在 Direct 与 Staged 流程中保持一致。
7. 原始文件和原始候选不可变，任何修复结果都是具有父子关系的派生产物。

## 4. 非目标

第一版不包含以下能力：

- 训练端到端的神经网络 MoE；本设计是可独立演进的工作流级专家组合。
- 扩图、补绘、生成新视角、生成缺失主体或生成缺失动作。
- 让大模型重新选择候选的时间起止点，或用生成内容修补动作和转场。
- 将成人内容识别、安全分类或用户偏好混入客观美学质量分。
- 自动覆盖原始文件、自动覆盖已发布结果或未经确认直接发布修复产物。
- 以多个提示词重复询问同一个模型，并把这些回答伪装成独立专家。
- 在本设计阶段修改数据库、运行时配置或候选处理代码。

## 5. 已确认的产品规则

### 5.1 内容中立

- 客观质量评分不读取成人内容标签，不因人物身份、题材或性暗示本身加减分。
- 成人与非成人候选使用同一个评分量表、同一阈值和同一最终裁决提示词。
- 内容安全、合规策略和用户偏好是独立层，只能在客观质量决策之后另行处理。
- 任何专家因内容拒答时，状态必须记为 `ABSTAINED`；不得转成零分、失败分或拒绝理由。

### 5.2 确定性门槛优先

- 已确认的硬转场、严重损坏、无可解码帧、动作完整性硬失败等确定性门槛不可由最终裁决模型覆盖。
- 硬门槛通过不等于候选优秀，只代表候选有资格进入软质量评估。
- 硬门槛失败的候选不进入可挽救性分支，因为曝光或重构图不能修复时间边界、损坏文件或残缺动作。

### 5.3 高精度拒绝

- 软质量自动拒绝必须同时满足：最终裁决置信度不低于 `0.80`，并且至少存在两个独立信号族的负面证据。
- 同一模型的不同提示词、不同采样轮次或同一特征的重复表达，只能算一个信号族。
- 未达到自动拒绝证据要求时，只能进入 `REVIEW`、`ABSTAIN` 或可挽救性分支。
- 阈值可通过版本化配置提高；降低拒绝保护门槛必须形成新的策略版本并重新通过校准验收。

### 5.4 可挽救候选

- 第一版只允许使用原始像素的光度和几何变换，不产生不存在于原始素材中的视觉信息。
- 修复专家只提出有限集合中的 `recipe_id`；最终裁决只能选择已实际生成并重新评分的代理，不得凭文本虚构参数。
- GIF 修复参数必须在整段上保持一致，或使用经过约束的平滑轨迹；不允许逐帧独立优化造成闪烁或镜头抖动。
- 原始候选始终保留，修复代理和正式修复产物都必须引用原始父产物。

## 6. 总体架构

```text
候选已物化
    |
    v
确定性硬门槛
    | 失败 ----------------------------> REJECT（硬门槛）
    v
低成本专家并行评估
    |- 技术/美学 VQA
    |- 时间连续性、动作、循环
    `- 轻量电影语言分析
    |
    v
证据归一化与路由
    |- 明确高质量 ----------------------> 统一裁决
    |- 明确低质量或灰区 ----------------> 可挽救性分支
    `- 专家冲突 ------------------------> 高成本专家
                                           |
                                           v
                                    可挽救性分支（需要时）
                                           |
                                           v
原始媒体 + 联系表 + 专家证据 + 最佳修复代理
                                           |
                                           v
                                  统一视频大模型裁决
                                           |
                 +-------------------------+--------------------------+
                 v                         v                          v
             KEEP_AS_IS             KEEP_FOR_REPAIR       REVIEW/REJECT/ABSTAIN
                 |                         |
                 `------------- 客观质量通过候选 ------------'
                                           |
                                           v
                                  用户偏好重排与后续导出
```

专家模型负责提供互补证据，Core 负责路由、策略、权限、状态和最终落库。大模型是受约束的裁决者，不是任务状态机，也不拥有文件覆盖、发布或修改时间边界的权限。

在目标桌面架构中，确定性 Task Engine 和质量评估服务由捆绑的 Core 运行时管理；审阅仍由原生桌面 GUI 承担。专家权重和内部推理进程应随安装目录捆绑，或复用现有 Ollama 模型服务，不得引入需要用户单独安装和维护的第二个外部服务。

## 7. 专家组成

### 7.1 确定性资格专家

复用并加强现有转场、动作完整性、时长、解码和循环检查，输出：

- 是否存在内部硬切或明显不连续转场；
- 动作是否有可接受的起点、主体阶段和结束点；
- 首尾是否适合循环，或是否存在明显跳变；
- 是否存在无法解码、严重丢帧或媒体损坏；
- 资格结论及可定位的帧区间。

它是硬策略来源，不参与软分数投票。

### 7.2 技术与美学 VQA 专家

首选候选为 DOVER-Mobile 或经基准验证的等价模型，分别输出技术质量与美学质量，重点覆盖：

- 清晰度、噪声、压缩、曝光、色彩异常；
- 构图、主体显著性、视觉舒适度和总体美感；
- 连续视频中的整体质量，而非只看代表帧。

DOVER 官方仓库使用非商用许可。若 GifAgent 的分发或使用场景不满足许可证，DOVER 只能用于研究验证，生产版本必须切换到许可证兼容且通过同一验收集的实现。许可证不允许通过打包方式规避。

### 7.3 时间、动作与循环专家

复用 GifAgent 已有的时间证据，统一转换为标准证据格式：

- 时间稳定性、运动连续性和镜头抖动；
- 主体动作完整性和裁切风险；
- 循环接缝质量；
- 转场邻近风险和候选边界置信度。

该专家主要由确定性计算机视觉与时间统计组成，与语义大模型属于不同信号族。

### 7.4 电影语言专家

使用 FilmOps 风格的电影语言操作符或通过本项目校准的等价模型，分析：

- shot scale；
- camera angle；
- camera movement；
- composition；
- lighting；
- color。

该专家不直接决定好坏，而是将镜头语言变成可解释属性与异常证据。例如“低调光”本身不是缺陷；只有主体信息不可辨、动态范围崩溃或表达目的与实际效果冲突时，才形成负面证据。

### 7.5 质量问答专家

在灰区或专家冲突时调用 VQA² 风格的视觉问答质量专家，以固定问题集检查：

- 最影响观看体验的缺陷是什么；
- 缺陷是技术失败还是有意的风格；
- 问题发生在全片还是局部时间段；
- 当前问题能否通过允许的非生成式变换改善；
- 修复是否会损伤主体、动作、构图或时间稳定性。

第一版不要求每个候选都调用此高成本专家。

### 7.6 可挽救性专家

只对以下候选运行：

- 没有硬门槛失败；
- 当前质量处于低分或灰区；
- 主要缺陷属于曝光、色调、轻度水平倾斜或构图问题；
- 预估修复成本属于低成本范围。

可挽救性专家生成有限数量的低分辨率代理，使用相同或兼容的专家重新评分，输出当前质量、最佳可恢复质量、预期增益和具体配方。

## 8. 证据协议

每个专家必须输出统一的 `ExpertEvidence`，不得把自由文本直接当成唯一依据。

```json
{
  "candidate_id": "candidate-123",
  "evaluation_version": "quality-moe-v1",
  "expert_id": "dover-mobile",
  "expert_version": "model-or-code-version",
  "signal_family": "nr_vqa",
  "status": "AVAILABLE",
  "scores": {
    "technical_integrity": 0.42,
    "spatial_aesthetics": 0.61
  },
  "findings": [
    {
      "code": "underexposed_subject",
      "severity": 0.63,
      "confidence": 0.88,
      "frame_start": 0,
      "frame_end": 47
    }
  ],
  "summary": "主体整体偏暗，但高光未明显剪切。",
  "input_hash": "sha256:...",
  "config_hash": "sha256:...",
  "prompt_hash": null,
  "latency_ms": 421
}
```

`status` 只允许：

- `AVAILABLE`：证据有效；
- `UNAVAILABLE`：依赖缺失、超时或运行错误；
- `ABSTAINED`：专家看到了输入但拒绝或无法作出适用判断；
- `INVALID`：输出不能通过结构校验。

除 `AVAILABLE` 外的状态都不得换算为零分。

### 8.1 独立信号族

第一版定义以下独立信号族：

- `deterministic_temporal`：转场、动作、循环和时间统计；
- `nr_vqa`：基于像素与视频特征的无参考质量模型；
- `cinematic_classifier`：电影语言操作符；
- `semantic_video_critic`：观看视频并进行语义质量分析的视觉大模型；
- `repair_delta`：真实修复代理与原始候选之间的重评分差值。

统一裁决模型自己的视觉观察属于 `semantic_video_critic`，不能再按其理由数量重复计票。共享相同基础模型或相同主要特征的两个实现，默认视为同一个信号族，除非离线消融实验能证明错误不相关并更新策略版本。

## 9. 可挽救性变换

### 9.1 光度变换

第一版允许以下整图或整段一致的变换：

- 曝光补偿候选：`-0.75`、`-0.35`、`+0.35`、`+0.75` EV；
- gamma 候选：`0.85`、`1.15`；
- 对比度调整：不超过 `±10%`；
- 阴影提升或高光压缩：不超过 `15%`；
- 白平衡温度/色调修正：单通道增益偏移不超过 `8%`。

组合搜索必须受配置上限控制，单候选最多生成 `12` 个代理。第一版 GIF 使用整段一致的光度参数，不做逐帧自动曝光。高光或阴影已经永久剪切时，不得声称恢复了不存在的细节。

### 9.2 几何变换

第一版允许：

- 使用原始像素进行固定裁切、缩放和重构图；
- 在不暴露空白边缘的前提下进行不超过 `2°` 的水平校正；
- 轻度透视校正，任一角点位移不超过对应边长的 `2%`；
- 输出画幅必须符合目标 GIF/图片的既定比例规则。

裁切后保留面积不得低于原始画面的 `70%`，等效放大不得超过 `1.25x`。主体、脸部和关键动作轨迹必须保持在安全区内。

GIF 优先使用固定裁切。只有在主体跟踪连续、轨迹置信度满足配置门槛、且输出通过抖动与边缘测试时，才允许使用平滑虚拟重构图轨迹；该轨迹必须由受限曲线生成，不能逐帧独立寻找最优裁切。

### 9.3 修复成立条件

`KEEP_FOR_REPAIR` 必须同时满足：

1. 最佳代理的客观质量达到保留阈值；
2. 相对于原始候选的归一化质量增益不低于 `0.15`；
3. 修复置信度不低于 `0.80`；
4. 没有新增硬门槛失败、时间闪烁、主体裁切、动作损伤或明显清晰度损失；
5. 统一裁决模型在同时观看原始与最佳代理后确认改善；
6. 最终输出引用一个已经生成并验证过的 `recipe_id`。

`0.15` 是第一版的初始安全门槛，进入生产自动决策前必须在校准集上验证。校准结果可以提高门槛；如需降低，必须发布新策略版本并重新验收。

## 10. 统一裁决

### 10.1 输入

最终裁决模型接收：

- 原始 GIF、视频候选或静态图片；
- GIF/视频的 6 至 8 帧带时间标签联系表；
- 所有有效、不可用和弃权的专家状态；
- 证据协议中的结构化分数、缺陷位置和解释；
- 如运行了可挽救性分支，则同时提供原始候选和最佳修复代理；
- 确定性策略约束和允许选择的决策枚举。

### 10.2 输出

```json
{
  "decision": "KEEP_FOR_REPAIR",
  "confidence": 0.87,
  "current_quality": 0.48,
  "recoverable_quality": 0.72,
  "dimension_scores": {
    "technical_integrity": 0.56,
    "spatial_aesthetics": 0.69,
    "temporal_coherence": 0.84,
    "action_completeness": 0.91,
    "cinematic_execution": 0.65,
    "loop_quality": 0.79
  },
  "negative_signal_families": ["nr_vqa", "semantic_video_critic"],
  "reason_codes": ["underexposed_subject", "repair_gain_verified"],
  "selected_recipe_id": "repair-123-exposure-p035",
  "expert_disagreements": [],
  "summary": "动作和循环完整，主体偏暗；已验证的曝光代理显著改善且未引入闪烁。"
}
```

### 10.3 决策枚举

- `KEEP_AS_IS`：原始候选已经达到保留标准，不需要修复。
- `KEEP_FOR_REPAIR`：原始候选不应直接发布，但存在已验证的低成本非生成式修复方案。
- `REVIEW`：证据不足、专家冲突或决策接近阈值，需要人工判断。
- `REJECT`：硬门槛失败，或满足高精度软拒绝规则且不存在成立的修复方案。
- `ABSTAIN`：裁决模型拒答、输入覆盖不足或无法可靠适用量表。

最终裁决模型不得：

- 覆盖硬门槛；
- 自行修改候选起止时间；
- 引用不存在的修复配方；
- 把成人内容标签、题材偏好或安全策略当作客观质量理由；
- 直接执行文件写入、覆盖、发布、删除或数据库操作。

### 10.4 裁决模型上线门槛

裁决接口不绑定单一厂商或模型。候选模型必须支持连续视频或等价的多帧输入、结构化输出和本地可复现配置，并通过本文第 16 节验收。

在没有模型通过校准集之前，系统只能以 `report_only` 运行：可以记录专家证据和建议，但软质量结论不能自动删除或拒绝候选。模型更换必须生成新的 `evaluation_version`，旧证据不被静默重解释。

## 11. 路由与成本控制

1. 所有候选先执行确定性硬门槛。
2. 通过者执行低成本专家：技术/美学 VQA、现有时间专家和轻量电影语言专家。
3. 明显高质量候选可以跳过高成本质量问答，但仍必须经过统一裁决形成正式决策。
4. 低分、灰区或低成本专家冲突的候选进入质量问答或可挽救性分支。
5. 可挽救性分支只保留最佳代理及必要的对照证据，不把所有搜索代理长期保存。
6. 专家缓存只用于性能优化；缓存丢失不得改变业务正确性。

路由阈值、模型版本和最大代理数量全部冻结进任务配置，运行中的任务不接受环境变量或全局配置漂移。

```yaml
    cinematic:
      enabled: true
      model_id: bundled-or-configured-model
    quality_qa:
      enabled: true
      route: gray_or_conflict
  judge:
    model_id: configured-video-model
    temperature: 0
    schema_version: quality-judge-v1
  repairability:
    enabled: true
    max_proxy_variants: 12
    min_quality_gain: 0.15
    min_confidence: 0.80
    photometric_mode: clip_global
    geometric_mode: fixed_or_validated_smooth
```

任务启动时，Core 必须把解析后的完整配置、模型摘要和提示词摘要写入任务快照。配置校验失败时，质量 MoE 不得启动；不能以隐藏默认值继续运行。

## 12. 数据与溯源

建议使用版本化、追加写的质量记录，逻辑实体至少包括：

- `quality_assessment`：候选的一次完整质量评估与最终决策；
- `expert_evidence`：单个专家的一次结构化证据；
- `repair_proposal`：修复参数、代理、增益和验证状态；
- `derived_artifact`：正式修复产物与原始产物的父子关系。

每次评估必须记录：

- 输入媒体哈希、候选时间边界和帧采样信息；
- 专家/裁决模型名称、版本和权重哈希；
- 完整配置哈希、策略版本和提示词哈希；
- 运行状态、耗时、错误类型和重试次数；
- 原始证据、归一化证据和最终裁决；
- 修复配方及其代理/正式产物哈希；
- 操作者、任务和评估时间。

原始媒体不可变。低分辨率搜索代理可按保留策略清理；一旦用户批准某个修复方案，正式派生产物及其完整溯源必须持久保存。

Direct 与 Staged 模式必须共享同一评估服务和协议。Staged manifest 需要版本化扩展以携带证据引用，不能依靠重新扫描目录推断状态。

## 13. 与现有排序的关系

- 客观质量裁决发生在用户偏好重排之前。
- `REJECT` 和 `ABSTAIN` 不参加正常偏好排序；`ABSTAIN` 保留在人工复核队列。
- `KEEP_AS_IS` 使用原始候选参加偏好重排。
- `KEEP_FOR_REPAIR` 使用已验证的可恢复质量参与候选展示，但未生成正式修复产物前不得作为完成品发布。
- 现有 `final_score` 可暂时作为兼容展示字段，但不能替代结构化证据、决策枚举和策略版本。
- 偏好模型可以在已通过客观质量门槛的候选之间排序，但不能把客观 `REJECT` 重新提升为可发布候选。

## 14. 审阅界面与操作权限

Core 对外提供稳定的候选质量读取与修复请求接口，原生桌面审阅界面只负责展示和收集决策。界面至少展示：

- 最终决策、置信度和六个质量维度；
- 原始候选与最佳修复代理的并排或切换对比；
- 专家证据、冲突、弃权和不可用状态；
- 具体修复配方、预期增益和可能副作用；
- “保留原始”“批准生成修复产物”“人工拒绝”和“稍后复核”等显式操作。

批准生成修复产物可以创建派生文件，但不能覆盖原始文件。覆盖导出目标、发布或替换既有结果仍属于高风险操作，必须由 Core 基于精确操作和目标路径再次授权，不能只依赖提示词约束。

## 15. 错误与降级

- 单个专家超时、依赖缺失或推理失败：记为 `UNAVAILABLE`，继续收集其余证据。
- 成人或敏感内容导致模型拒答：记为 `ABSTAINED`，不得形成负分。
- 可用独立信号不足：进入 `REVIEW`，不能自动软拒绝。
- 裁决输出结构不合法：使用同一输入进行一次结构修正重试；仍失败则进入 `ABSTAIN`。
- 修复代理生成失败：保留原始候选和原始质量结论，记录失败，不把代理失败当成候选质量差。
- 修复后出现闪烁、主体裁切或新的硬门槛：该配方失效，不能输出 `KEEP_FOR_REPAIR`。
- 媒体损坏或无可解码帧：按确定性硬门槛拒绝该候选，但单候选失败不导致整个任务失败。
- 运行恢复：以持久化证据和评估版本为准，可安全重算缺失步骤；缓存不是状态真相。

## 16. 测试与验收

### 16.1 单元测试

- 证据结构校验、状态枚举和分数归一化；
- 独立信号族去重，证明同一模型多次回答不会增加票数；
- 硬门槛不可覆盖；
- 自动软拒绝的双信号与置信度规则；
- 成人拒答只生成 `ABSTAINED`；
- 修复搜索上限和所有光度/几何边界；
- 配方只能引用实际生成的代理；
- 原始文件不可变和父子产物关系；
- Direct/Staged 同配置得到一致的策略路径。

### 16.2 合成与回归测试

覆盖：欠曝、过曝、白平衡偏移、噪声、压缩、失焦、故意颗粒、故意运动模糊、镜头抖动、固定构图偏差、主体边缘裁切、硬切、渐变转场、残缺动作、首尾跳变和修复引入闪烁。

必须验证：

- 曝光与色调修复不会造成逐帧闪烁；
- 固定或平滑重构图不会露出空白边缘或切断关键主体；
- 低调光、风格化色彩、手持摄影和故意模糊不会被简单规则一律判差；
- 硬转场与动作残缺不能通过美学高分或修复分支逃逸。

### 16.3 人工校准集

生产自动决策前建立不少于 `200` 个候选的分层校准集，同时包含 GIF、静态图片和视频候选。至少覆盖：

- 常规电影镜头、动画和强风格作品；
- 明亮、低调光和高反差场景；
- 快速动作、慢速运动、固定镜头和手持镜头；
- 成人与非成人内容；
- 明显低质量、边界样本、可修复样本和不可修复样本。

每个样本至少由两名人工审阅者独立标注“当前质量”“是否应保留”“是否可通过允许的变换修复”和理由。争议样本经第三人裁定，形成金标准和一致性统计。

### 16.4 上线验收指标

- 自动软拒绝精确率不低于 `95%`；覆盖率不设最低要求，宁可进入人工复核。
- 经人工确认可修复的候选，`KEEP_FOR_REPAIR` 召回率不低于 `80%`。
- `KEEP_FOR_REPAIR` 的盲评对比中，最佳修复产物优于原始候选的比例不低于 `70%`。
- 修复后新增硬转场、动作残缺、空白边缘或时间闪烁的样本数为 `0`。
- 任何评估和修复都不修改原始文件，原始哈希保持率为 `100%`。
- 在质量分层匹配后，成人与非成人样本的误拒绝率差不超过 `5` 个百分点。
- 同一输入、模型、权重、配置和提示词在确定性专家上结果完全一致；裁决模型温度为零时，决策枚举复测一致率不低于 `95%`。
- 所有已完成评估都能从记录中还原输入哈希、模型版本、配置、提示词、专家证据和最终策略路径。
- Direct 与 Staged 模式在相同冻结配置下的最终决策一致率为 `100%`。

任何一项关键指标未通过时，只能继续 `report_only` 或人工复核模式，不能启用自动软拒绝。

## 17. 分阶段上线与回滚

1. **影子评估**：只记录专家证据和建议，不影响现有候选排序与导出。
2. **人工复核**：展示统一裁决和修复代理，但所有 `REJECT` 与 `KEEP_FOR_REPAIR` 由人工确认。
3. **受限自动化**：校准指标通过后，允许确定性硬门槛与满足双信号规则的高置信软拒绝自动生效；修复仍生成派生结果，不自动发布。
4. **稳定运行**：持续抽样人工复核，监测模型漂移、内容分层误差和可修复性收益。

所有阶段由版本化配置控制，只影响新任务。回滚时停用新的路由或自动策略，历史评估、人工反馈和派生产物保持可读，不删除证据。

## 18. 明确延期：生成式视角与补绘

以下能力登记为后续独立设计，不进入第一版：

- outpainting/扩图；
- 生成原画面不存在的新视角；
- 基于深度或多帧推断进行生成式视角移动；
- 生成缺失背景、主体、肢体或动作；
- 使用生成模型修补被裁掉的内容。

后续若实现，必须满足：

- 生成产物显式标记为生成内容，不能冒充原始镜头；
- 使用独立评分、独立血缘和独立发布权限；
- 原始与生成结果并排人工复核；
- 不得因为生成版本存在而删除原始候选；
- 需要单独的安全、身份一致性、时序一致性和版权风险设计。
