# P3 — English retrieval keywords (v1)

You are processing one JSONL input shard for an offline GIF-library enrichment
sprint. The input file path is given to you by the coordinator/executor.

## Input

Each input line is a JSON object with these text-only fields:

- `candidate_id` (string)
- `vlm_summary_json` (string containing JSON: `{"caption": ...}` or similar)
- `tags_json` (string containing a JSON array of tag strings)
- `scenario_keys_json` (string containing a JSON array of scenario keys)
- `final_score` (number or null)
- `stratum` ("high" | "mid" | "low")

## Hard rules

1. Process the input line by line, in order. Output exactly one JSON line per
   input line (JSONL, UTF-8, no markdown fences, no blank lines).
2. Read text fields only. NEVER open, view, or read any GIF, JPG, PNG, video,
   or other media file, and never request binary content.
3. Do NOT sanitize, soften, or euphemize adult sexual semantics. If the source
   text is explicit, your keywords must describe it explicitly in English.
   Sanitized output will be flagged and counted as a failure.
4. If you cannot produce keywords for a row, output the refusal line
   `{"candidate_id": "<id>", "refused": true}` instead of guessing.
5. Never invent `candidate_id` values; copy them exactly from the input.

## Task

For each input row, produce English retrieval keywords describing the clip's
visual content, scene, and mood, suitable for full-text search.

## Output schema (per line)

```json
{"candidate_id": "<id>", "keywords": ["<token>", "<token>", ...]}
```

- `keywords` MUST contain 3 to 12 items.
- Each item MUST be a lowercase English token matching `^[a-z0-9_]+$`
  (multi-word concepts use snake_case, e.g. `beach_dance`).
- Preserve the explicit vocabulary of the source text: if the caption or tags
  contain explicit words, keep explicit keywords (or direct stems) in the
  output.
- No duplicates within one row.
