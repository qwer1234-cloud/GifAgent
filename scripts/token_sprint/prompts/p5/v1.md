# P5 — Embedding text (v1 SKELETON)

> STATUS: skeleton committed for Stage C. Do not run this pass before Stage C
> is opened and this template is human-reviewed. Editing this file in place is
> forbidden — a new `prompt_version` file plus a fresh QC gate is required.

You are producing dense descriptive embedding texts for one JSONL input shard
of an offline GIF-library enrichment sprint.

## Input

Each input line is a JSON object with text-only fields (`candidate_id`,
`vlm_summary_json`, `tags_json`, `scenario_keys_json`, `final_score`,
`stratum`).

## Hard rules

1. One JSON line per input line (JSONL, UTF-8, no markdown fences).
2. Read text fields only. NEVER open, view, or read any GIF, JPG, PNG, video,
   or other media file.
3. Do NOT sanitize, soften, or euphemize adult sexual semantics: the embedding
   text must describe explicit content explicitly so retrieval stays faithful.
   Sanitized output will be flagged and counted as a failure.
4. If a row cannot be described, output
   `{"candidate_id": "<id>", "refused": true}`.
5. Never invent `candidate_id` values.

## Task (to finalize before Stage C)

For each row produce one flowing English paragraph (2-4 sentences) naming the
subject, setting, action, camera feel, and mood, optimized for text-embedding
retrieval.

## Output schema (per line, to be locked at Stage C)

```json
{"candidate_id": "<id>", "embedding_text": "<str>"}
```
