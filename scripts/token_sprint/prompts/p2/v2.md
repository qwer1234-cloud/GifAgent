# P2 — Scene metadata extraction (v2)

You are extracting structured scene metadata from one JSONL input shard for an
offline GIF-library enrichment sprint.

## Input

Each input line is a JSON object with text-only fields (`candidate_id`,
`caption`, `vlm_summary_json`). The `caption` field carries the VLM caption
text and is the sole evidence for the optional facets defined below.

## Hard rules

1. Process the input line by line, in order. Output exactly one JSON line per
   input line (JSONL, UTF-8, no markdown fences).
2. Read text fields only. NEVER open, view, or read any GIF, JPG, PNG, video,
   or other media file.
3. Do NOT sanitize, soften, or euphemize adult sexual semantics: describe the
   scene as explicitly as the source text warrants. Sanitized output will be
   flagged and counted as a failure.
4. If a scene cannot be described for a row, output the refusal line
   `{"candidate_id": "<id>", "refused": true}` instead of guessing.
5. Never invent `candidate_id` values; copy them exactly from the input.

## Task

For each input row, describe the scene with three required facets:

- `setting`: the location/environment (e.g. `bedroom`, `beach`, `night_club`,
  `studio`) — null when unknown.
- `act`: the main action or activity performed (explicit when the content is
  explicit) — null when unknown.
- `finish`: how the clip ends or its resolution/mood (e.g. `climax`,
  `applause`, `loop`, `fade_out`) — null when unknown.

Plus up to two OPTIONAL facets. These are a strict source-verbatim mapping of
the input `caption` text, not free-form generation:

- `exposure` (optional): the state of dress or nudity that the caption states
  (e.g. `nude`, `topless`, `lingerie`, `underwear`, `shirtless`).
- `mood` (optional): the emotional tone or expression that the caption states
  (e.g. `smiling`, `serious`, `playful`, `distressed`).

### Source-verbatim constraint (v2, locked)

For an optional facet, include the key ONLY when its value can be found
verbatim in the input caption text:

- The value (lowercased, with `_` read back as a space) must appear in the
  caption as a contiguous, case-insensitive substring.
- Never paraphrase, translate, stem, or otherwise normalize a facet value the
  caption does not literally contain. If the evidence is absent, OMIT the key
  entirely (do not emit null for an optional facet).
- Optional facets never invent words. The required facets keep the v1
  semantics and may still be null when unknown.

## Output schema (per line)

```json
{"candidate_id": "<id>", "prompt_version": "p2/v2", "prompt_sha256": "<sha256-of-this-prompt-file>", "scene": {"setting": "<str|null>", "act": "<str|null>", "finish": "<str|null>", "exposure": "<str>", "mood": "<str>"}}
```

- `scene` MUST be a JSON object containing at least the keys `setting`, `act`,
  `finish`. Additional keys are allowed; any value may be null.
- `exposure` and `mood` are optional: either include the key with a
  source-verbatim string value, or omit the key. Never emit them as null.
- Values are short lowercase English `snake_case` phrases when not null.
- `prompt_version` is the literal string `p2/v2` and `prompt_sha256` is the
  SHA-256 of this prompt file, copied unchanged into every output line.
