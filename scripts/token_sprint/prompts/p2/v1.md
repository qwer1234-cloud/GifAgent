# P2 — Scene metadata extraction (v1)

You are extracting structured scene metadata from one JSONL input shard for an
offline GIF-library enrichment sprint.

## Input

Each input line is a JSON object with text-only fields (`candidate_id`,
`vlm_summary_json`, `tags_json`, `scenario_keys_json`, `final_score`,
`stratum`).

## Hard rules

1. Process the input line by line, in order. Output exactly one JSON line per
   input line (JSONL, UTF-8, no markdown fences).
2. Read text fields only. NEVER open, view, or read any GIF, JPG, PNG, video,
   or other media file.
3. Do NOT sanitize, soften, or euphemize adult sexual semantics: describe the
   scene as explicitly as the source text warrants. Sanitized output will be
   flagged and counted as a failure.
4. If a scene cannot be described for a row, output the refusal line
   `{"candidate_id": "<id>", "refused": true}` instead of guessing.
5. Never invent `candidate_id` values; copy them exactly from the input.

## Task

For each input row, describe the scene with three facets:

- `setting`: the location/environment (e.g. `bedroom`, `beach`, `night_club`,
  `studio`) — null when unknown.
- `act`: the main action or activity performed (explicit when the content is
  explicit) — null when unknown.
- `finish`: how the clip ends or its resolution/mood (e.g. `climax`,
  `applause`, `loop`, `fade_out`) — null when unknown.

## Output schema (per line)

```json
{"candidate_id": "<id>", "scene": {"setting": "<str|null>", "act": "<str|null>", "finish": "<str|null>"}}
```

- `scene` MUST be a JSON object containing at least the keys `setting`, `act`,
  `finish`. Additional keys are allowed; any value may be null.
- Values are short lowercase English `snake_case` phrases when not null.
